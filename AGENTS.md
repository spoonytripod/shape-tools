# Repository Guidelines

## Project Structure & Module Organization

- `src/app/` contains the Next.js App Router pages and global CSS. `/` lists the tools; `/tools/pyramid`, `/tools/stairs`, and `/tools/circular-arrows` host the generators.
- `src/components/tools/tool-editor.tsx` handles controls and previews. `src/components/ui/` contains shadcn/ui components. Pure SVG generators live in `src/lib/tools/`; shared color, ratio, and download helpers live in `src/lib/shared/`.
- `tests/` contains SVG regression fixtures and browser tests. `docs/` holds goals, migration status, conventions, and decisions. Root `index.html` still serves the old GitHub Pages demo; `legacy/` is reference material.

## Build, Test, and Development Commands

- `npm ci`: install exactly the dependencies in `package-lock.json`.
- `npm run dev`: start the Next.js app at `http://localhost:3000`.
- `npm run typecheck`, `npm run lint`, `npm run format:check`: check TypeScript, ESLint, and Prettier.
- `npm test`: compare generated SVG with the original app's recorded output.
- `npm run build`: create a production build. `npm run test:e2e`: exercise routes, controls, and downloads in Chromium; install it first with `npx playwright install chromium`.

## Coding Style & Naming Conventions

Use two-space indentation, semicolons, single-quoted strings, camelCase for values/functions, PascalCase for React components/types, and kebab-case for filenames. Run Prettier and ESLint on new code. Keep geometry independent of React and the DOM; use Client Components for controls and browser APIs. Reuse shadcn/ui components and common design tokens. Keep SVG colors in hex, backgrounds transparent, and PNG's long edge at 2048 px.

## Testing Guidelines

Name calculation tests `*.test.ts` and browser flows `*.spec.ts`. Cover changed geometry and boundary values with meaningful assertions. After shared changes, check all three tools, five aspect ratios, SVG/PNG downloads, and narrow layouts. The original output fixture is generated by `scripts/capture-legacy-baseline.mjs`; update it only for an intentional output change and explain why.

## Commit & Pull Request Guidelines

Use concise scoped messages such as `feat(stairs): add height control` or `docs: update migration plan`. PRs should describe the changed behavior, related issues, validation, and any limitations. Include before/after images for visual changes and representative exports for rendering changes. Run `git diff --check` before submitting.
