# 0001. 프로젝트 방향과 TypeScript 전환

- 상태: 방향 유효, 기술 선택은 [0002](0002-next-shadcn-vercel.md)에서 구체화
- 날짜: 2026-09-25
- 근거: 프로젝트 소유자의 목적 및 전환 요청

## 배경

발표 자료와 문서에 필요한 모형을 만드는 개인 도구로 시작했다. 도형 종류와 사용자를 늘리려면 단일 파일의 스타일·상태·기하 계산을 나눠 관리할 필요가 있다.

## 결정

- HTML·CSS·TypeScript를 기반으로 역할과 도형별 모듈을 분리한다.
- 브라우저에서 생성하고 SVG/PNG로 내려받는 흐름을 유지한다.
- 공개 웹사이트에서 다른 사람도 쉽게 사용할 수 있도록 발전시킨다.
- 목표·전환 계획·규약·기술 선택 근거를 저장소의 `docs/`에서 관리한다.
- 기존 세 도형을 보존하며 전환하고 이후 실용 도형을 확장한다.

## 영향과 대안

TypeScript를 브라우저용 JavaScript로 변환하는 개발·빌드 절차가 필요하다. 단일 HTML 파일을 직접 열던 개발 방식과 배포 절차는 바뀔 수 있다.

단일 파일 유지도 가능하지만 확장 시 책임 분리가 어렵다. 프레임워크 도입과 배포처는 당시 미결정이었고 [0002](0002-next-shadcn-vercel.md)에서 정했다. 서버 기반 생성과 사용자 계정도 초기 범위 밖이다.

## 미결정 사항

Next.js·shadcn/ui·Vercel은 [0002](0002-next-shadcn-vercel.md)에서 결정했다. 패키지 관리자는 [0003](0003-package-manager.md)에서 npm으로, 테스트·린트·포맷 도구는 [0004](0004-quality-tooling.md)에서 정했다. 설치된 버전은 `package-lock.json`에 기록된다. Vercel 프로젝트 설정과 첫 신규 도형은 아직 정하지 않았다.

## 검증

[전환 계획](../migration-plan.md)의 단계별 완료 조건을 사용한다. 기존 출력 비교, 타입 검사·빌드, 공개 URL 동작, SVG/PNG 출력 품질을 근거로 전환 완료를 판단한다.
