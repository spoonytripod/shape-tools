# Next.js·TypeScript 전환 계획

상태: 계획 · 코드 전환 미착수

## 현재와 목표

현재 `index.html`에 스타일, 마크업, JavaScript가 함께 있다. 도형은 IIFE로 분리되어 있고 색상·비율·다운로드 함수를 공유한다. 패키지, 빌드, 자동 테스트 구성은 없다. `legacy/`는 참고 자료다.

목표는 Next.js App Router와 TypeScript로 화면·상태·기하 계산을 구성하고, shadcn/ui를 공통 UI 컴포넌트에 적용하는 것이다. 도형 생성과 SVG/PNG 다운로드는 브라우저에서 실행한다. Vercel을 목표 배포처로 삼는다. 선택 근거는 [후속 결정 기록](decisions/0002-next-shadcn-vercel.md)에 있다.

## 목표 구조

아래는 구현 계획이며 아직 생성된 구조가 아니다.

```text
src/
  app/
    layout.tsx             # 공통 레이아웃
    page.tsx               # 도형 목록 (/)
    tools/
      pyramid/page.tsx     # /tools/pyramid
      stairs/page.tsx      # /tools/stairs
      circular-arrows/page.tsx # /tools/circular-arrows
    globals.css            # 공통 스타일과 디자인 토큰
  components/
    ui/                    # shadcn/ui 컴포넌트
    tools/                 # 도형별 조절 UI
  lib/
    shared/                # 색상, 비율, 내보내기, 공통 타입
    tools/
      pyramid/             # 상태·기하·SVG 생성
      stairs/
      circular-arrows/
public/                   # 필요할 때만 사용하는 정적 파일
tests/                    # 계산 및 주요 사용자 흐름 검증
docs/                     # 목표, 계획, 규약, 결정 기록
legacy/                   # 이전 구현 참고용
```

## 단계별 작업과 완료 조건

### 1. 기준 동작 확보 — 미착수

- 세 도형의 기본값·최솟값·최댓값, 팔레트, 방향, 모든 비율을 점검한다.
- 대표 미리보기와 SVG/PNG 파일, 재현 파라미터, 확인 브라우저를 기록한다.
- 완료 조건: 전환 후 비교할 기준 결과와 기존 문제 목록이 있다.

### 2. Next.js 기반 구성 — 미착수

- npm으로 기존 저장소에 Next.js App Router·React·TypeScript를 구성한다. `package-lock.json`을 추적하고 정확한 버전은 설치 시 기록한다.
- shadcn/ui를 구성하고 필요한 컨트롤 컴포넌트만 추가한다. 기존 CSS의 공통 색상과 간격을 새 스타일 체계로 옮긴다.
- 개발 서버, 타입 검사, ESLint, Prettier, 빌드 명령을 정의하고 README에 실제 명령을 기록한다. Vitest로 공유 계산을 검증할 수 있게 한다. 브라우저 흐름 검증에는 Playwright를 구성한다.
- 완료 조건: 새 환경에서 기존 화면의 기본 골격이 실행되고 타입 검사와 빌드가 통과한다.

### 3. 도형 모듈 전환 — 미착수

- 공유 함수를 분리한 뒤 피라미드 → 계단 → 원형 화살표 순서로 옮긴다.
- 상태 타입, 입력 범위, SVG 생성 함수, React UI 연결을 분리한다. 기하 계산은 DOM 없이 실행되게 한다. 슬라이더·색상 선택·다운로드처럼 상호작용하는 부분은 Client Component에서 처리한다.
- [URL 결정](decisions/0005-url-structure.md)에 따라 도형별 경로를 만들고, 새 사이트의 기존 `#page-*` 링크를 대응 경로로 연결한다.
- 도형별로 기준 결과와 비교한다. 구조 변경과 의도적인 디자인·기하 변경을 별도 변경으로 나눈다.
- 완료 조건: `/`의 도형 목록, 세 도형의 직접 링크·새로고침, 새 사이트의 기존 해시 링크 연결이 동작하고 공유 기능의 회귀 검증이 통과한다.

### 4. 공개 배포 준비 — 미착수

- 전환한 앱의 동작을 검증한 뒤 Vercel 프로젝트·도메인 설정을 결정한다. Git 저장소를 연결하고 Preview·Production 배포 흐름을 구성한다. 기존 GitHub Pages 데모의 안내와 전환 시점을 정리한다.
- 직접 링크·새로고침, 모바일 화면, 키보드 조작, 다운로드 실패 안내를 점검한다.
- SVG/PNG 출력물의 크기, 투명도, 시각적 품질을 확인한다. 이전 배포 버전으로 복구하는 절차도 기록한다.
- 완료 조건: Vercel의 공개 URL에서 생성·내보내기를 검증하고 지원 범위와 알려진 제한을 문서화한다.

### 5. 도형 확장 — 미착수

- 실제 사용 사례로 후보를 선정하고 공통 모듈 계약에 맞춰 추가한다.
- 완료 조건: 신규 도형의 사용 예시·경계값 검증·내보내기 확인·문서 갱신이 끝난다.

## 보존해야 할 동작

미리보기와 다운로드는 동일한 SVG 생성 로직을 사용한다. 투명 배경, SVG hex 색상, SVG 크기와 viewBox의 일치, PNG 긴 변 2048px, 선택 비율을 유지한다. 팔레트 변경이 항목 수를 바꾸지 않게 하고 도형 사이 상태가 섞이지 않게 한다.

각 단계는 리뷰 가능한 변경으로 나누고 기존 동작을 검증한 다음 진행한다. 기존 구현 삭제는 대체 구현 검증 이후에 수행한다.
