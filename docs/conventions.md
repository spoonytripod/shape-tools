# 개발·문서 규약

상태: 적용 중 · 실행 명령은 루트 README 참조

## 구현 원칙

- Next.js App Router에서 의미 있는 HTML과 입력 레이블을 사용한다. 버튼과 조절기는 키보드로 접근할 수 있게 한다.
- shadcn/ui 컴포넌트와 공통 디자인 토큰을 재사용한다. 도형별 스타일이 다른 도형에 영향을 주지 않게 한다.
- TypeScript는 엄격한 타입 검사를 기준으로 한다. 도형 상태와 옵션 타입을 정의하고 무분별한 `any`와 타입 단언을 피한다.
- 2칸 들여쓰기, 세미콜론, 작은따옴표를 따른다. 변수·함수는 camelCase, 타입은 PascalCase, 상수는 UPPER_SNAKE_CASE, 파일·폴더는 kebab-case를 사용한다.
- 전환 전 코드는 기존 IIFE 패턴을 따른다. 새 코드는 React 컴포넌트와 TypeScript 모듈로 구성한다. 브라우저 API, 입력 상태, 다운로드를 쓰는 컴포넌트에 Client Component 경계를 둔다. 신규 의존성은 목적과 비용을 결정 기록에 남긴다.
- 패키지는 npm으로 관리한다. 의존성 변경 시 `package.json`과 `package-lock.json`을 함께 커밋하고, CI·배포의 재현 가능한 설치에는 `npm ci`를 사용한다.

## 도형 모듈 계약

각 도형은 고유 ID, 기본 상태, 허용 범위, SVG 생성 진입점, React 컨트롤 컴포넌트 책임을 갖는다. 구체적인 공통 인터페이스는 기존 세 도형을 옮기며 확정한다.

색상 보간, 캔버스 크기, 파일 다운로드는 공유 모듈을 사용한다. SVG 생성은 입력 상태로부터 결정 가능한 결과를 반환하고 DOM 이벤트 처리는 별도 책임으로 둔다. 계산의 단위와 제한 이유를 주석으로 설명한다.

## 검증과 완료 기준

[품질 도구 결정](decisions/0004-quality-tooling.md)에 따라 다음을 검증한다.

- Vitest 단위 검증: 색상 보간, 비율별 캔버스 계산, 도형 경계값과 유효 좌표. 파일명은 `*.test.ts`로 한다.
- Playwright 브라우저 검증: 도형 선택, 값 변경, 미리보기, SVG/PNG 다운로드. 파일명은 `*.spec.ts`로 한다.
- 수동 검증: 화면 크기별 배치, 투명도, 시각적 품질, SVG/PNG 출력 품질.

새 코드의 정적 검사에는 ESLint와 Next.js 권장 규칙을, 서식에는 Prettier를 사용한다. TypeScript 타입 검사는 별도로 실행한다. 임의의 커버리지 비율을 목표로 정하지 않는다. 변경된 계산과 실패하기 쉬운 경계 조건을 검증한다. 버그 수정은 가능한 경우 재현 검증을 포함한다. 공유 기능 변경은 세 도형 모두 확인한다.

완료 보고에는 변경 목적, 실행한 검증, 결과, 남은 제한을 적는다. UI 변경에는 전후 이미지, 출력 변경에는 대표 파일과 재현 파라미터를 제시한다.

## 커밋과 리뷰

커밋은 `docs:`, `refactor(pyramid):`, `feat(stairs):`, `fix(export):`처럼 목적과 범위가 드러나게 작성한다. 구조 전환과 신규 기능은 가능한 한 별도 변경으로 나눈다.

PR에는 문제·변경 후 동작·검증 결과·관련 문서 또는 이슈를 적는다. 의존성이나 배포 변경은 설정 이유와 복구 방법도 설명한다. 생성 파일과 로컬 다운로드 결과물을 무분별하게 커밋하지 않는다.

## 문서 관리

- 본문은 한국어, 파일명은 영문 소문자와 하이픈을 사용한다. 코드 식별자와 명령은 원문을 유지한다.
- 목표는 `project-goals.md`, 일정 없는 단계별 계획은 `migration-plan.md`, 규약은 이 문서를 기준으로 삼는다.
- 실행 명령과 실제 기능 변경 시 루트 README를, 단계 시작·완료 시 전환 계획과 문서 목차의 상태를 함께 갱신한다.
- 기능 추가 시 사용 사례·입력 범위·출력 예시를 기능 문서에 남기고 목차에 연결한다.
- 파일 추가·이동 시 목차와 상대 링크도 수정한다. 동일한 설명은 복사보다 링크를 우선한다.
- 확정 방향, 구현 사실, 제안을 구분한다. 검증 근거가 있을 때만 완료로 표시한다.
- 중요한 선택은 `decisions/NNNN-short-title.md`에 번호, 날짜, 상태, 배경, 결정, 영향, 대안, 검증 방법을 기록한다.
- 결정 변경 시 후속 기록으로 대체하고 양방향 링크를 남긴다. 이전 기록은 삭제하지 않는다.
- 제안 상태 자체가 별도 승인 절차를 뜻하지 않는다. 범위 안의 기술 선택은 근거를 기록하며 진행한다.
- AGENTS.md와 CLAUDE.md는 공통 규약을 연결하고 현재 구현과 목표 구조를 구분한다. Vercel 배포 구성과 공개 URL이 확정되면 README도 갱신한다.
